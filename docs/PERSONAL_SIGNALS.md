# Персональные сигналы и подключение BingX

## Поведение

- Только USDT-фьючерсы BingX. Пользователь вводит API Key и API Secret в настройках Mini App. Проверяются доступ на чтение баланса, позиций и открытых ордеров. Интеграция не выставляет, не изменяет и не отменяет ордера.
- Ключи зашифрованы Fernet и привязаны к Telegram ID внутри шифротекста. Клиенту возвращается только окончание API Key. Поля формы очищаются после отправки; localStorage и sessionStorage для ключей не используются.
- Для позиции используется `balance` фьючерсного USDT-счёта. Это баланс кошелька, а не `equity` с нереализованным PnL и не `availableMargin`. Существующая формула, процент риска и ограничения контракта сохранены в `miniapp/sizing.py` и `trading/trade_plan.py`.
- Баланс обновляется перед расчётами в командах, автосигналах и Mini App. При ошибке подключённого аккаунта старое значение не выдаётся за свежий расчёт; сигнал остаётся доступен без размера позиции. Нулевой баланс никогда не заменяется примером на 1 000 USDT. Для пользователей без API сохранён прежний ручной депозит.
- Источник набора монет — первые 100 монет CoinGecko по `market_cap_rank`, пересечённые с активными фьючерсами BingX. Если часть монет отсутствует на бирже, список содержит меньше 100: монеты ниже сотого места не добавляются. Есть явные соответствия для контрактов с множителем (например, PEPE → 1000PEPE).
- Рейтинг обновляется раз в час. При временном сбое используется последний успешный список не старше шести часов; без него новые предложения приостанавливаются. Сопровождение уже выбранных сделок продолжается.
- Группы сохраняются на сервере и применяются до ограничения длины выдачи. `NULL` означает все группы, `[]` — ни одной. Старые профили сохраняют доступ ко всем группам до собственного выбора. Каталог сервера и браузера проверяется на совпадение.
- «Я в сделке» подписывает только на выбранный сигнал. Одновременно можно сопровождать разные монеты и направления. Повторное нажатие не создаёт дубликата. Одновременно привязать два сигнала одного рынка и направления нельзя: они неотличимы в общей позиции биржи.
- «Я вышел» прекращает сопровождение и отменяет ожидающие отправки сообщения этой сделки. Старая кнопка входа после выхода не возобновляет подписку. Новые сигналы по выбранным группам продолжают приходить. Изменение групп и состава топ-100 не отменяет активные подписки.
- Цена TP1, TP2 и стопа отслеживается по исходному сигналу. Подтверждение исполнения TP1 отправляется отдельно, только для связанного ордера с `FILLED` и положительным `executedQty`; частичное исполнение не объявляется полным.
- Привязка требует единственной позиции нужного рынка и направления и единственного TP-ордера на уровне TP1 с точностью контракта. Неоднозначные ордера или несовпадающие уровни остаются неподтверждёнными. UI показывает отсутствие привязки. В этом случае уведомления по цене продолжаются. Уже исполненный до привязки ордер не объявляется исполненным предположительно.
- Проверка личных ордеров выполняется отдельным циклом с паузой 30 секунд между проходами; время прохода зависит от числа пользователей. Ошибка одной монеты не отменяет успешные проверки остальных. Переподключение или удаление аккаунта сбрасывает активные связи ордеров.
- Новые обычные сигналы `/plan`, `/scan`, `/digest` и автоматическая рассылка используют общий шаблон. События сопровождения имеют общий формат с номером сделки, монетой, направлением, уровнем и указанием источника подтверждения.
- Генерация скальпов и отдельных SMC Setup отключена. Они исключены из новых сохранений, рассылки и пользовательской выдачи. Старые записи базы остаются сохранёнными. `/setup` открывает обычный план; `/spikes` сообщает об удалении режима.
- Новые настройки личного риска и отдельный дисклеймер «сверьтесь с вашим риском» не добавляются. Ранее существующие настройки формулы сохраняются.

## Конфигурация и выпуск

1. Установить зависимости из `requirements.txt` и `miniapp/requirements.txt`.
2. Один раз создать Fernet-ключ стандартным `cryptography.fernet.Fernet.generate_key()` и сохранить одинаковое значение `BINGX_CREDENTIALS_KEY` в секретах сервиса бота и Mini App. Не добавлять ключ в Git или журналы. Потеря/смена ключа без миграции потребует повторного подключения пользовательских API-ключей.
3. При необходимости указать `COINGECKO_DEMO_API_KEY` для лимитов публичного рейтинга.
4. Оба сервиса должны использовать одну PostgreSQL. Миграция `011_personal_bingx_signals.sql` аддитивная и применяется существующим механизмом блокировки миграций. Она прекращает старые ожидающие уведомления, поскольку получение сигнала больше не означает участие в сделке.
5. Выпускать бот и Mini App согласованно. Не оставлять старый worker с логикой массового сопровождения после включения новой схемы.

Без `BINGX_CREDENTIALS_KEY` форма подключения вернёт понятную ошибку; работа старых пользователей без API продолжится. Реальные ключи вводятся пользователем только в форме приложения. Для проверки публикации достаточно тестового аккаунта с правами чтения: финансовые операции интеграции не нужны.

## Проверка

`python -m pytest -q` запускает модульные и регрессионные проверки. Тесты `tests/test_personal_trading.py` дополнительно проверяют шифрование, подпись запросов, неизвестные группы, нулевой баланс, неоднозначность ордеров и разницу ценового события/исполнения.

При `TEST_DATABASE_URL` на локальную базу с именем `ucb_test…` интеграционные тесты создают отдельные временные схемы: повторное применение миграции, два пользователя, сохранение групп до пагинации, вход/выход, отмена очереди и изоляция исполнений. В CI предусмотрен временный PostgreSQL.

`node --test tests/asset_groups.test.cjs tests/asset_icons.test.cjs` проверяет каталоги. `tests/ui_signal_groups.cjs` запускается через Playwright против localhost с подменёнными ответами API. Проверяются сохранение трёх групп, откат ошибки, перезагрузка, сопровождение, подключение/отключение ключей, отсутствие секретов в браузерном хранилище, пять языков и четыре размера экрана.

Проверки не отправляют реальные уведомления и не используют реальные аккаунты BingX. Полный цикл с фактическим исполнением пользовательского ордера требует проверки на аккаунте после настройки окружения.

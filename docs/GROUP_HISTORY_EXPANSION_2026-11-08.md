# Групповые стратегии: расширение истории и первая новая гипотеза

Статус на 8 ноября 2026: **офлайн-исследование, не обновление торговых правил**. Скринер, `/plan`, Telegram, GitHub main и Railway не менялись. Цель 20 разных сетапов в неделю остаётся ориентиром, не обязательной квотой.

## История монет

Из 111 инструментов каталога 27 уже имели проверенные исторические 4H-снимки. По сохранённой проверке BingX от 7 ноября заранее выбраны ещё 25: активный контракт, три снимка стакана, отсутствие флагов ликвидности, полная тогдашняя 30-дневная проверка данных и указанное биржей время запуска до 1 марта 2026 года. Приоритет загрузки — сначала по одному инструменту каждой доступной группы, затем следующие по наблюдавшемуся 24-часовому обороту. Отбор не использовал результат сделок.

Для всех 25 публичный API BingX вернул проверяемые, непрерывные 4H-ряды: по 1 509 свечей, всего 37 725; пагинация и хеши сохранены. Ошибок и пропусков нет. Период тот же, что у исходных 27: март — 7 ноября 2026 года. Ещё 35 инструментов исключены из этого расширения из-за флагов ликвидности на снимке, 2 — из-за даты запуска контракта, 22 новых инструмента каталога пока не имеют сопоставимого аудита ликвидности.

Важно: ноябрьский снимок не доказывает историческую ликвидность, отсутствие делистинга в прошлом или тогдашний размер ценового шага. Эти монеты не получают экономический допуск задним числом. Для них ещё не проверены паспорт токена/контракта и дополнительный бенчмарк группы.

## Частота при прежних правилах

| Разработческая выборка | Технических кандидатов за 17 полных недель | Консервативно разных идей | Недель с 20+ кандидатами |
| --- | ---: | ---: | ---: |
| Исходные 27 | 50 | 30 | 0 |
| Дополнительные 25, без паспортов | 8 | 6 | 0 |
| Все 52, исключительно технический экран | 58 | 36 | 0 |

Максимум в одной неделе расширенной выборки — 18 сырых кандидатов. Это **не** число отправленных сигналов и даже не строгая верхняя граница: для новых инструментов ещё нет всех индивидуальных проверок, а текущие метаданные контракта не являются историческими. Повтор на уже просмотренном периоде не может подтвердить доходность или будущую частоту.

## Первая новая гипотеза входа

Для сторон групп, где профиль уже использует трендовый вход, отдельно протестирован 4H inside-bar после закрытого дневного тренда. Предыдущая 4H-свеча — «материнская»; текущая целиком внутри неё, меньше по диапазону и объёму, закрывается в сторону тренда. Вход возможен только при пробое границы материнской свечи; стоп стоит за её противоположной границей. Дневной режим, BTC-контекст, возраст тренда и прочие первоначальные фильтры сохранены. Гипотеза применялась только там, где исходный кандидат дошёл до проверки 4H-цены и был отвергнут ею.

На исходных 27 инструментах это добавило **3 технических кандидата**, а число консервативно разных идей выросло с 30 до 31. Этого недостаточно для задачи частоты. Запускать такой вход пользователям **не следует**; исполнения по минутным данным, funding, комиссий, проскальзывания, стопов и просадки для трёх новых идей ещё нет.

## Что проверяем дальше

1. Доработать паспорта и индивидуальные бенчмарки 25 новых инструментов, начиная с проверки точной идентичности токена и контракта. Не объединять XAUT и PAXG в одно доказанное правило только потому, что оба отнесены к RWA.
2. Зафиксировать отдельные 4H-гипотезы для пробойных групп (масштабирование, приватность, AI, данные, мемы, игры, приложения) и диапазонных режимов ETH/платежей. Трендовый inside-bar уже проверен и не дал нужного прироста; повторно подбирать его пороги по этим же датам нельзя.
3. Для **всех** новых кандидатов выбранной версии собрать минутное исполнение и исторический funding, учесть комиссии и проскальзывание, затем сравнить стопы, просадку и итог после расходов по группе и направлению.
4. Оценивать правила на новом независимом периоде отдельно от уже просмотренной истории и от существующего замороженного forward-эксперимента. Без этого не повышать частоту живого сканера.

Код и результаты воспроизводятся локально: `evaluation/group_history_expansion.py` фиксирует выборку и собирает свечи только с явным `--collect`; `evaluation/group_expansion_scan.py` делает технический экран; `evaluation/group_inside_bar_trial.py` проверяет первую 4H-гипотезу. Сырые ответы BingX хранятся в отдельной игнорируемой Git папке `output/group-history-expansion-20261108/`.

Источники подхода: [официальный справочник рыночных данных BingX](https://github.com/BingX-API/api-ai-skills/blob/main/skills/swap-market/SKILL.md); [исследование риска переобучения бэктестов](https://escholarship.org/uc/item/4w1110bb). Наличие API-данных или известного паттерна не доказывает прибыльность стратегии.
